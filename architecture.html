System Architecture Diagrams

Development View Architecture Diagram

Figure 1: Development View Architecture Diagram. This diagram adopts a layered architectural pattern and shows the system's static decomposition from the development perspective. It is a conventional "box-and-line" diagram that organizes the system into three tiers—Presentation, Business, and Data Layers—clearly depicting the major subsystems and their unidirectional dependencies. This view guides modular implementation and code organisation.

Execution View Architecture Diagram

Figure 2: Process/Runtime View Architecture Diagram. This diagram illustrates the dynamic runtime interactions from the process perspective, focusing on component communication and the flow of control. It traces the complete request-response cycle from the browser-based front-end, through the API Gateway and Prediction Engine, to the Map Database and back, enabling analysis of system performance and runtime non-functional characteristics.

Database Architecture Diagram

Figure 3: Database Pipeline Architecture Diagram. Raw New York City urban datasets are spatially processed using NumPy to generate an aggregated feature matrix. Then,the machine learning model XGBoost, predicts environmental noise levels, while SHAP provides feature explanations and confidence indicators that reflect the reliability of each prediction.
